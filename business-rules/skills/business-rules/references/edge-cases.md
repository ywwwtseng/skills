# 邊界條件 Checklist

規則草稿寫完後，看功能涉及哪些面向，逐項檢查。每一項的答案要嘛已有規則覆蓋，要嘛寫成一條新規則或一條假設；不能空著。

## 金額 / 數值

- [ ] 0、負數、極大值（超過上限）各自怎麼處理？
- [ ] 小數：允許幾位？在哪一步進位？用哪種進位？
- [ ] 幣別：單一幣別還是多幣別？匯率取哪個時點？
- [ ] 折扣疊加：多個折扣的順序與是否可疊加？折後金額可為負嗎？
- [ ] 累計值（累計消費、點數）：退款 / 取消時要扣回嗎？扣回後等級會降嗎？
- [ ] 顯示值與計算值是否一致（顯示四捨五入但內部保留小數）？

## 時間

- [ ] 時區：以哪個時區判定？使用者跨時區時以誰為準？
- [ ] 「當天」「本月」「本週」的起訖（週一起還是週日起？）
- [ ] 邊界瞬間：剛好等於期限（10:05:00）算內還是外？
- [ ] 滑動窗口 vs 固定區間
- [ ] 假日 / 營業日：定義來源、順延規則
- [ ] 夏令時間、閏年、月底（1/31 + 1 個月 = ?）
- [ ] 資料時間 vs 處理時間：以事件發生時間還是系統收到時間為準？
- [ ] 逾時：從什麼時候起算？狀態改變會重置計時嗎？

## 數量 / 集合

- [ ] 空集合（訂單沒有任何品項）？
- [ ] 一個 vs 多個（單品項 vs 多品項是否適用同規則）？
- [ ] 上限：一次最多幾筆？超過時拒絕還是截斷？
- [ ] 重複項（同一商品出現兩列）合併還是拒絕？
- [ ] 部分成功（10 筆中 3 筆失敗）：全部回滾還是部分套用？

## 身分 / 相同性

- [ ] 「同一使用者」的判定：帳號？Email？手機？裝置？
- [ ] 「同一商品」的判定：SKU？SKU + 規格？名稱？
- [ ] 訪客（未登入）適用嗎？登入後合併嗎？
- [ ] 帳號合併 / 刪除後歷史紀錄歸誰？
- [ ] 代理操作（客服代客戶做）：規則以誰為主體？

## 並發 / 重複

- [ ] 同一動作同時送兩次（連點、重試）：要冪等嗎？以什麼為冪等鍵？
- [ ] 兩個人同時改同一筆：後寫覆蓋、拒絕、還是合併？
- [ ] 檢查與執行之間狀態改變（檢查時庫存 1，執行時 0）？
- [ ] 限量資源（庫存、名額）的搶占順序？

## 狀態

- [ ] 每個狀態都有進入與離開的路徑嗎？（沒有離開路徑的是終態，要明說）
- [ ] 終態後的資料可以改嗎？可以查嗎？
- [ ] 中途失敗（付款到一半）落在哪個狀態？
- [ ] 逆向操作（取消已完成、退回上一步）允許嗎？限制？

## 刪除 / 修改

- [ ] 刪除是真刪還是標記？標記後對唯一性約束的影響（刪掉的 Email 能重新註冊嗎）？
- [ ] 有關聯資料時能刪嗎（有訂單的商品）？連帶刪除還是阻擋？
- [ ] 修改後歷史紀錄用舊值還是新值（商品改名，舊訂單顯示什麼）？
- [ ] 哪些欄位建立後不可改？

## 權限

- [ ] 每個動作都有明確的角色清單嗎？
- [ ] 自己的 vs 別人的（所有權）
- [ ] 角色變更後，進行中的東西怎麼辦（管理員降級，他建立的東西誰管）？
- [ ] 未登入 / 被停權的使用者能看到什麼？

## 外部依賴

- [ ] 外部系統（金流、物流、簡訊）失敗或逾時：主流程等待、失敗、還是先成功後補？
- [ ] 外部回傳與內部狀態不一致時以誰為準？
- [ ] 回呼（webhook）重複送達要防嗎？

## 回溯 / 遷移

- [ ] 新規則對既有資料是否生效？
- [ ] 不生效時如何區分新舊（以建立時間？以版本欄位？）
- [ ] 規則參數（5 分鐘、100 元）改變時，進行中的實體用新值還是舊值？

## 使用者可見性

- [ ] 被規則阻擋時使用者看到什麼？要說明原因嗎？要說明怎麼解嗎？
- [ ] 哪些規則要在事前提示（送出前就告訴他不行），哪些事後才擋？
- [ ] 錯誤訊息是否會洩漏不該知道的資訊（「此 Email 已註冊」）？
