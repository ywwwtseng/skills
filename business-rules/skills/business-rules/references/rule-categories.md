# 規則類別與 Checklist

八個類別依序走一遍。每個類別先看「這個功能有沒有這種東西」，有才寫；每個 checklist 項目若答案不是「不適用」，就要對應到至少一條規則或一條假設。

ID 前綴：`BR-<實體縮寫>-<三位流水號>`，類別不進 ID（見 `writing-rules.md`）。

## 1. 定義與推導值（Definition）

給名詞下精確定義，或定義由其他屬性算出來的值。沒有這一類，後面的規則會各自解讀同一個詞。

**Checklist**

- [ ] 需求裡每個名詞（「活躍客戶」「相同商品」「營業日」）有唯一定義嗎？
- [ ] 「相同」的判定基準是什麼？（同 SKU？同 SKU + 同規格？同名稱？）
- [ ] 推導值的資料來源與計算時機（即時算 / 每日快照）？
- [ ] 推導值在來源改變時是否重算？

**範例**

> BR-CUS-001 活躍客戶：過去 90 天內至少有一筆狀態為「已完成」的訂單的客戶。以查詢當下時間回推，不含當天。

## 2. 約束與驗證（Constraint）

「不可以」「必須」類規則：資料格式、範圍、唯一性、關聯完整性、業務前置條件。

**Checklist**

- [ ] 每個輸入欄位的必填 / 格式 / 長度 / 範圍？
- [ ] 唯一性：哪些欄位組合不可重複？範圍是全域還是某個父實體內？
- [ ] 前置條件：動作執行前實體必須處於什麼狀態、擁有什麼？
- [ ] 數量上限 / 下限（一筆訂單最多幾項、一人最多幾個帳號）？
- [ ] 違反時是「阻擋」「警告後放行」還是「自動修正」？
- [ ] 違反時的錯誤要讓誰看到、需要說明原因嗎？

**範例**

> BR-ORD-003 同商品重複下單限制：同一買家在 5 分鐘（滑動窗口）內，對同一商品（同 SKU）已有一筆狀態非「已取消」的訂單時，不得再建立含該商品的訂單。阻擋並回傳原因與可再下單的時間。

## 3. 計算（Calculation）

金額、數量、分數、排名等任何算式。

**Checklist**

- [ ] 算式本身（列出每一項與順序）
- [ ] 計算順序（先折扣再稅，還是先稅再折扣？多個折扣的疊加順序？）
- [ ] 進位規則：小數位數、四捨五入 / 無條件捨去 / 銀行家捨入、在哪一步進位
- [ ] 幣別與匯率：用哪個時點的匯率？
- [ ] 邊界：0、負數、超過上限時怎麼算？
- [ ] 計算結果是否凍結（訂單成立後價格改了，訂單金額跟著變嗎？）

**範例**

> BR-ORD-010 訂單應付金額 = Σ(單價 × 數量) − 折扣 + 運費，每一項單價 × 數量先四捨五入到整數，再加總。折扣不得使應付金額 < 0，低於 0 以 0 計。訂單成立時凍結，之後商品價格異動不影響。

## 4. 狀態流轉（State Transition）

實體有生命週期時，列出所有狀態與合法轉換。

**Checklist**

- [ ] 所有狀態的完整列表與初始狀態
- [ ] 每個合法轉換：從哪到哪、誰能觸發、前置條件、是否可逆
- [ ] 終態有哪些？終態後還能做什麼（查看？複製？）
- [ ] 非法轉換的行為（阻擋 / 忽略）
- [ ] 自動轉換（逾時、排程）的觸發條件
- [ ] 轉換時要同步發生什麼（見類別 7）

**輸出方式**：一張轉換表 + mermaid `stateDiagram-v2`，再為每個有條件的轉換寫一條規則。

| 從 | 到 | 觸發者 | 條件 | 規則 |
|---|---|---|---|---|
| 已送出 | 已取消 | 買家 | 尚未付款 | BR-ORD-020 |
| 已送出 | 已取消 | 系統 | 30 分鐘未付款 | BR-ORD-021 |

## 5. 權限（Authorization）

誰能對什麼做什麼。

**Checklist**

- [ ] 每個動作對應的角色清單
- [ ] 所有權：只能操作自己的？自己團隊的？全部？
- [ ] 狀態相關權限：某狀態下只有特定角色能改
- [ ] 代理 / 客服代操作：算誰的行為？要留紀錄嗎？
- [ ] 讀取權限與修改權限是否不同
- [ ] 欄位級權限（某些欄位只有管理員能看 / 改）

**輸出方式**：角色 × 動作矩陣，格子填 ✓ / ✗ / 條件（指向規則 ID）。

## 6. 時間與排程（Temporal）

任何涉及時間點、時間窗、期限、週期的規則。

**Checklist**

- [ ] 時區：以什麼時區判定「當天」「營業日」？
- [ ] 時間窗是滑動（過去 N 分鐘）還是固定區間（每個日曆日）？
- [ ] 邊界：剛好等於期限算內還是外？
- [ ] 營業日 / 假日如何定義？期限落在假日順延嗎？
- [ ] 排程任務的執行時間、頻率、錯過一次怎麼補
- [ ] 有效期間：開始 / 結束是含還是不含端點？
- [ ] 「立即」是多即時？可容忍延遲多久？

## 7. 觸發與副作用（Trigger）

某事發生後系統必須跟著做的事：通知、寄信、更新其他實體、寫紀錄、呼叫外部系統。

**Checklist**

- [ ] 每個狀態轉換 / 關鍵動作觸發哪些副作用？
- [ ] 副作用失敗時主動作要回滾嗎？還是主動作成功、副作用重試？
- [ ] 重複觸發（同事件送兩次）要防嗎？
- [ ] 通知對象、內容要素、時機（立即 / 彙整）
- [ ] 需要留審計紀錄的動作（誰、何時、改了什麼、改前改後）

## 8. 例外與覆寫（Exception / Override）

主規則的例外、人工介入、管理員覆寫。

**Checklist**

- [ ] 哪些主規則允許例外？例外條件是什麼？
- [ ] 誰能覆寫？需要理由 / 審核 / 紀錄嗎？
- [ ] 覆寫是一次性還是持續？
- [ ] 特殊客戶 / 測試帳號 / 內部人員是否豁免？
- [ ] 舊資料是否適用新規則（回溯）？不適用時如何區分新舊？

**寫法**：例外規則獨立 ID，並在主規則的「例外」欄引用。例：主規則 BR-ORD-003 的例外是 BR-ORD-004「客服代下單不受重複限制，但需填寫原因」。
