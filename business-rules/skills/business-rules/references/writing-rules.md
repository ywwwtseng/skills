# 規則寫法

## 單條規則格式

```markdown
### BR-ORD-003 同商品重複下單限制
- **陳述**：同一買家在 5 分鐘（滑動窗口）內，對同一商品（同 SKU）已有一筆狀態非「已取消」的訂單時，不得再建立含該商品的訂單。
- **類型**：約束
- **適用時機**：買家或客服送出訂單時
- **違反時**：阻擋，回傳原因與可再下單的時間
- **例外**：BR-ORD-004
- **範例**：
  | 情境 | 預期 |
  |---|---|
  | 10:00 下單 SKU-A，10:04 再下 SKU-A | 拒絕，提示 10:05 後可下單 |
  | 10:00 下單 SKU-A，10:05:00 再下 SKU-A | 允許（窗口為 5 分鐘，剛好等於視為超出） |
  | 10:00 下單 SKU-A 後取消，10:02 再下 SKU-A | 允許 |
  | 10:00 下單 SKU-A，10:02 下 SKU-B | 允許 |
- **來源**：需求
```

欄位說明：

| 欄位 | 必填 | 說明 |
|---|---|---|
| 陳述 | ✓ | 一句話，含主詞（誰 / 什麼）、條件、結果。不用「應該」「盡量」，只用「必須」「不得」「等於」 |
| 類型 | ✓ | 定義 / 約束 / 計算 / 狀態流轉 / 權限 / 時間 / 觸發 / 例外 |
| 適用時機 | ✓ | 指回 Step 1 的事件 |
| 違反時 | 約束類必填 | 阻擋 / 警告後放行 / 自動修正 / 忽略，以及誰看得到 |
| 例外 | 有才寫 | 引用例外規則 ID |
| 範例 | ✓ | 至少 2 個：一個正常、一個邊界。約束類要有一個「剛好在界線上」的案例 |
| 來源 | ✓ | 需求 / 推導 / 假設。假設要在文末「假設清單」再列一次 |

## ID 規範

- 格式 `BR-<實體縮寫>-<三位流水號>`，例：`BR-ORD-003`
- 實體縮寫 3 個大寫字母，一個功能內固定，在文件開頭「縮寫表」列出
- 流水號按實體遞增，不按類別分段；刪除規則保留號碼不重用，在「變更紀錄」標記為廢止
- 已存在的文件沿用既有縮寫與最大號碼接續

## 陳述句寫法

**好**

- 「訂單小計低於 100 元時不得送出」
- 「客戶等級每日 00:00（Asia/Taipei）依過去 365 天累計消費重算」

**不好 → 改法**

| 不好 | 問題 | 改成 |
|---|---|---|
| 訂單金額要合理 | 不可驗證 | 訂單小計必須介於 1 至 1,000,000 元（含） |
| 盡量避免重複下單 | 「盡量」無法判定 | 5 分鐘內相同商品不得重複下單 |
| 系統檢查 `orders.status` | 實作細節 | 訂單狀態為「已取消」時 |
| 使用者不能亂改 | 主詞與動作不明 | 買家僅能修改狀態為「草稿」的自有訂單 |
| 超過期限就處理掉 | 結果不明 | 送出後 30 分鐘未付款，系統自動轉為「已取消」 |

## 決策表

條件超過 2 個且互相組合時，改用決策表，比一堆 if-else 句子清楚：

```markdown
### BR-SHP-005 運費計算

| 訂單小計 | 配送地區 | 會員等級 | 運費 |
|---|---|---|---|
| ≥ 1000 | 任意 | 任意 | 0 |
| < 1000 | 本島 | 金卡以上 | 0 |
| < 1000 | 本島 | 其他 | 80 |
| < 1000 | 離島 | 任意 | 150 |

規則由上往下比對，取第一個符合的列。
```

決策表必須：欄位覆蓋所有組合（沒覆蓋到的組合視為遺漏，要補列或寫預設列）、標明比對順序。

## 優先序與衝突

兩條規則可能同時適用時：

1. 在較低優先的規則加一行 **優先序**：「與 BR-XXX-nnn 同時適用時以 BR-XXX-nnn 為準」
2. 補一個兩者同時觸發的範例
3. 通用原則：例外 > 主規則；明確指定 > 預設；阻擋 > 警告

## 常見的「一條變多條」

| 原句 | 拆成 |
|---|---|
| 5 分鐘內不能重複下單，除非是客服代下 | 主規則（約束）+ 例外規則（例外） |
| 付款後 7 天內可退款，退款要通知客戶 | 退款前置條件（約束）+ 退款成功通知（觸發） |
| 逾時自動取消並釋放庫存 | 自動取消（狀態流轉）+ 釋放庫存（觸發） |
