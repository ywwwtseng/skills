# 模型元素 → schema 元素對應

模型的每個元素都有固定的落地選項。先用這張總表定位，再看細則。

| 模型元素 | 預設落點 | 其他選項 | 決定關鍵 |
|---|---|---|---|
| 聚合 | 不是一張表，是交易邊界 | — | 同聚合的寫入必須在同一個交易內 |
| 聚合根（實體） | 一張表 | — | — |
| 聚合內實體 | 一張表 + 指回聚合根的外鍵 | — | 有自己的識別碼就獨立成表 |
| 值物件（單一值） | 攤平成該表的數個欄位，共用前綴 | 獨立表（被多表共用且需要一致更新時） | 會不會被單獨查詢 / 約束 |
| 值物件（集合） | 獨立表 + 指回擁有者的外鍵 | JSON 陣列（不需查詢與約束時） | 有沒有 per-item 的不變量 |
| 列舉 | 文字欄位 + CHECK | 原生 enum、對照表 | 值會不會由使用者新增、引擎能力 |
| 衍生屬性 | 不存，查詢時算 | 存成欄位（凍結值、查詢熱點） | 模型有沒有寫「凍結」 |
| 不變量 | DB 約束 | 應用層交易內檢查 | 見下方「不變量 → 約束」 |
| 關聯 | 外鍵 | join table、應用層維護 | 基數與是否同一個庫 |
| 狀態機 | 現值欄位 + CHECK | 另加歷史表 | 規則需不需要回查轉換歷史 |
| 命令 | 不建表；決定索引與交易 | — | 每個命令的查詢路徑要有索引支撐 |
| 領域事件 | 不建表 | outbox 表（需可靠送達時） | policy 失敗會不會造成業務問題 |
| Policy（排程） | 不建表；決定索引 | 任務表（需要記錄執行狀態時） | 需不需要冪等與重試紀錄 |

## 概念型別 → 欄位型別

模型的概念型別（`docs/domain/model` 只用這些）對應如下。各引擎的實際型別名見 `dialects.md`。

| 概念型別 | 關聯式落地 | 注意 |
|---|---|---|
| 識別碼 | UUID / 文字（ULID）/ 自增整數 | 全 schema 統一一種，見 `conventions.md` |
| 文字 | 變長文字，無長度上限或給寬鬆上限 | 有格式要求 → 加 CHECK；長度上限只在規則有寫時才設 |
| 整數 | 整數型別；依範圍選寬度 | 會成長的計數用 64 位元 |
| 小數 | 定點數（精度 / 小數位明寫） | 不要用浮點數存需要精確比較的數 |
| 金額 | 整數（最小單位）或定點數 + 幣別欄位 | 全 schema 統一一種，見 `conventions.md` |
| 時間點 | 帶時區的時間戳（UTC 儲存） | 見 `conventions.md` 時間段 |
| 日期 | 日期型別 | 模型標了時區就在欄位說明寫明依哪個時區切日 |
| 時長 | 整數 + 單位寫進欄位名（`ttl_seconds`） | 不要用字串 |
| 期間 | 兩個欄位（`*_start_at`、`*_end_at`）+ CHECK | 端點含不含照模型；PostgreSQL 可用 range 型別 |
| 布林 | 布林型別 | 不要用來表示狀態（狀態用列舉） |
| 列舉〈X〉 | 見上表列舉段 | 值與模型列舉表逐一對齊 |
| 〈實體〉參照 | 外鍵欄位 `<實體>_id` | 跨聚合是否建實體外鍵要明寫 |
| 集合〈X〉 | 獨立表；模型標「有序」→ 加 `position` 欄位 + 複合唯一 | 上下限（1..50）落成應用層檢查並記進落點表 |
| 可選〈X〉 | NULL 可空 | 模型寫的「沒有值代表什麼」抄進欄位說明 |

## 值物件的三種落法

| 落法 | 何時用 | 代價 |
|---|---|---|
| 攤平（前綴欄位） | 單一值、欄位數 ≤ 4、需要查詢或約束 | 每個使用它的表都要重複這幾個欄位 |
| 獨立表 | 集合型、或多表共用且要一起更新 | 多一次 join |
| JSON | 結構不固定、不查詢、不約束（例：外部回傳的 raw payload） | 無法下 CHECK、索引受限、之後拆表要回填 |

攤平時前綴用模型的屬性名（`total` + `Money` → `total_amount`、`total_currency`），不要把值物件名塞進欄位名。可空的攤平值物件要用 CHECK 保證「全部為 NULL 或全部有值」。

## 關聯 → 鍵

| 模型基數 | 落地 | 外鍵位置 | NULL |
|---|---|---|---|
| `1 → 0..*` | 外鍵 | 「多」的那一側 | NOT NULL |
| `0..1 → 0..*` | 外鍵 | 「多」的那一側 | 可空 |
| `1 → 1` | 外鍵 + UNIQUE | 依擁有權，被擁有的一側 | NOT NULL |
| `0..1 → 1` | 外鍵 + UNIQUE | 選填的那一側 | 可空 |
| `*..*` | join table（複合主鍵）| — | 兩欄皆 NOT NULL |
| `1 → 1..N`（上限） | 外鍵 + 應用層檢查上限 | 「多」的那一側 | NOT NULL |

`ON DELETE` 照模型關聯的「解除時機 / 對方消失時」：

| 模型寫法 | ON DELETE |
|---|---|
| 擁有權為「擁有」、隨父一起刪 | `CASCADE` |
| 保留識別碼、對方消失不影響 | `SET NULL`（欄位須可空），或不建實體外鍵 |
| 禁止對方被刪 | `RESTRICT` |
| 軟刪除 | 不用 `ON DELETE`；改由軟刪除欄位與應用層規則處理 |

跨聚合的關聯：同一個資料庫 → 仍建外鍵（一致性優先），並在該表註明「跨聚合參照，寫入不共用交易」；跨服務 / 跨庫 → 不建外鍵，欄位照建，落點表寫明由哪個命令維護一致性。

## 不變量 → 約束

| 模型的不變量型態 | 落點 | 實作 |
|---|---|---|
| 屬性必填 | DB | NOT NULL |
| 值域 / 範圍 / 長度 | DB | CHECK |
| 列舉值 | DB | CHECK 或原生 enum |
| 欄位間關係（起 < 迄） | DB | CHECK |
| 全域唯一 | DB | UNIQUE |
| 某父實體內唯一 | DB | 複合 UNIQUE（父 id + 欄位） |
| 帶條件的唯一（僅某狀態） | DB（支援部分索引時）/ 應用層 | 部分唯一索引；不支援則交易內檢查 + 序列化隔離 |
| 集合數量上下限 | 應用層 | 交易內 `COUNT` + 鎖父列；上限很關鍵時可加計數欄位 + CHECK |
| 跨表 / 跨聚合條件 | 應用層 | 命令交易內檢查；寫明鎖定範圍 |
| 狀態機的合法轉換 | 應用層 | 命令前置條件；DB 只用 CHECK 守「值必須是合法狀態之一」 |
| 需要外部資料 | 應用層 | 寫明失敗處理 |

落點表每條都要寫「檢查時機」（哪個命令、交易內或交易前）與「違反時」（拒絕 / 修正 / 警告），照模型命令表的「失敗時」欄。

## 狀態機的落地

- 現值：一個欄位 + CHECK（或 enum），預設值取模型的初始狀態。
- 轉換合法性：應用層守；在落點表寫明「由命令 X 的前置條件檢查」。
- 進入某狀態的時間點：模型有寫（`cancelled_at`）才加欄位，不要每個狀態都加。
- 歷史表：只在規則需要回查（稽核、申訴、統計停留時長）時建，欄位為 `<實體>_id`、`from`、`to`、`command`、`actor`、`occurred_at`，標「儲存衍生」。

## 常見錯誤

| 錯誤 | 為什麼不好 | 改法 |
|---|---|---|
| 一個聚合一張表，內部實體塞 JSON | 內部實體的不變量守不住、無法查詢 | 聚合內實體各自成表，用外鍵與交易維持邊界 |
| 值物件一律開表 | 單值物件多一次 join 卻沒好處 | 單一值攤平成前綴欄位 |
| 狀態用布林欄位組合 | 非法組合擋不住，和模型狀態機對不上 | 一個狀態欄位 + CHECK |
| 模型的不變量沒進落點表 | 規則沒人守，測試也看不出來 | 逐條指派落點，守不了就寫明並列進未落地 |
| 把所有外鍵都設 `CASCADE` | 刪一列連帶刪掉不該刪的資料 | 照模型關聯的擁有權決定 |
| 為每個欄位建索引 | 寫入變慢、佔空間，仍沒命中實際查詢 | 每個索引寫出它支援的命令 / 查詢 |
| 欄位名與模型屬性名對不上 | 日後改規則找不到要改哪一欄 | 命名照 `conventions.md`，來源欄指回模型屬性 |
| 在 schema 裡「順便」加模型沒有的業務欄位 | 領域概念繞過模型偷偷長出來 | 標「儲存衍生」或回 `/domain:model` 補模型 |
| 衍生屬性一律存成欄位 | 來源變了忘了重算，資料對不上 | 只存模型寫「凍結」或確有查詢需求的，並寫明維護者 |
