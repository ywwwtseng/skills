# 狀態清單

每個畫面都要走完這份清單（SKILL 核心規則 2）。每個狀態回答三題：**顯示什麼**、**使用者能做什麼**、**資料怎麼來**。

不適用的明確寫「不適用 — 〈理由〉」。留空分不出是不需要還是忘了寫。

## 通用（所有平台）

| 狀態 | 要決定的事 |
|---|---|
| **初次載入** | 骨架屏、轉圈、還是先顯示快取？空白畫面超過一秒就要有東西 |
| **載入更多** | 分頁時的位置與行為；載入中能不能繼續捲動 |
| **空** | 從來沒有資料 vs 篩選後沒結果，**這兩個要分開**：前者給引導與主要動作，後者給「清除篩選」 |
| **錯誤** | 整頁錯誤 vs 保留舊資料加一條錯誤提示；有沒有重試按鈕 |
| **部分失敗** | 列表載入成功但某個區塊失敗時，其他部分還要不要顯示 |
| **權限不足** | 整頁擋掉、還是隱藏部分內容；訊息要不要說明缺什麼權限 |
| **唯讀** | 因狀態或權限不可編輯時，欄位怎麼呈現（灰掉 vs 純文字） |
| **資料過期／已被刪除** | 進來時目標已不存在（別人刪了、狀態變了）要顯示什麼、返回哪裡 |
| **成功** | 動作完成後：留在原地更新、跳轉、還是關閉；提示用 toast 還是行內 |

## 表單

| 狀態 | 要決定的事 |
|---|---|
| **未填 / 部分填** | 送出按鈕何時可用；是不是即時驗證 |
| **驗證失敗** | 錯誤標在欄位旁還是頂端摘要；何時觸發（輸入中、失焦、送出時） |
| **送出中** | 按鈕轉圈並鎖住、整頁鎖住、還是可以取消 |
| **送出失敗（可重試）** | 使用者填的內容要保留，**這條最常被漏掉** |
| **重複送出** | 連點兩次、或網路逾時後重送 → 對應契約的冪等鍵 |
| **離開未存** | 攔截並提示，還是自動存草稿 |

## 行動端（有 iOS / Android 時全部必寫）

| 狀態 | 要決定的事 |
|---|---|
| **離線** | 顯示快取＋離線標記、還是整頁擋掉；哪些動作允許離線排隊 |
| **送出中斷網** | 排進佇列稍後重送、還是直接失敗；使用者怎麼知道它還沒送出去 |
| **弱網（很慢但沒斷）** | 逾時多久、逾時後給什麼選項 |
| **背景喚醒** | 回到前景時資料已過期：自動重新整理、還是顯示「資料可能已過期」 |
| **推播進入** | 從推播直接開啟這個畫面時，返回堆疊怎麼組；目標資源已不存在怎麼辦 |
| **深連結進入** | 同上，另外要處理「未登入時開深連結」 |
| **系統權限被拒** | 相機、通知、定位、相簿被拒且不再詢問時，畫面怎麼引導到系統設定 |
| **鍵盤遮擋** | 輸入時被遮住的元素怎麼處理（捲動、縮排、浮動送出列） |
| **返回手勢** | 多步驟流程中滑動返回的行為；會不會遺失輸入 |
| **首次啟動** | 冷啟動時還沒有任何快取，跟「空」不同 |
| **登入過期** | token 失效時：靜默刷新、還是跳登入並記住原本要去哪 |

## 對照檢查

寫完狀態矩陣後，回頭對三份文件核一次：

1. **契約的每個錯誤碼** → 是不是都能對到上面某個狀態（SKILL Step 5）
2. **模型的每個狀態** → 詳情畫面在那個狀態下顯示什麼、哪些動作可用
3. **BR 的每個失敗情境** → 使用者在畫面上怎麼知道、怎麼處置

三項都對得上，這個畫面的規格才算寫完。
