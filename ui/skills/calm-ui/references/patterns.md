# 版型與文案

五種畫面的具體長相。值用 `tokens.css` 的 token，判準見 `../SKILL.md`。

文案範例是**語氣的示範**：Agent 用第一人稱、講已經做完的事、給一個明確的下一步。不要照抄字串。

## Agent Feed（首頁）

```
早安，William

3 件事需要你注意


10:30 – 11:00

產品會議
我已經準備好會議摘要了。

查看摘要 →

────────────────────────

API 文件

執行中 · 80%
████████████░░

────────────────────────

David 已經等你回覆兩天了

我擬好了一份回覆。

查看 →
```

版型規則：

- 問候 + **一句話說明現況**（「3 件事需要你注意」），這一句就是三秒法則的答案
- 每個項目：**上下文**（時間 / 對象）→ **標題** → **Agent 已經做了什麼** → **一個動作**
- 項目之間用 `--space-6` 以上的留白與一條極淡的分隔線，**不要用卡片**
- 排序依「需要注意的程度」，不是時間、不是分類
- 自然混合：需要注意的、Agent 正在做的、即將發生的、等待核准的、最近完成的
- 最多 5–7 項。更多就是首頁在推責任給使用者

**不要做成 widget 格狀牆**，也不要把「今日待辦 / 進行中 / 已完成」做成三個分頁——那是在要求使用者自己分類。

## 對話

多數訊息就是文字：

```
你的會議 10:30 開始。

我準備好摘要了，另外找出三個
需要你決定的事項。

查看摘要 →
```

**只有在能讓動作更好做時**才引入結構化 UI（核准、確認、選擇、進度、排程、外部動作、審閱產出）。例如需要核准時：

```
我可以幫你回覆 David。

┌─────────────────────────┐
│ 「這週五前我會給你完整   │
│  的規格，先確認方向是    │
│  不是這樣……」           │
└─────────────────────────┘

  傳送     修改     不用了
```

規則：

- 引用產出的內容用表面色塊（`--color-surface`）+ `--radius-md`，不是一張帶標題列的卡片
- 選項用文字按鈕橫排，主要動作在最左或最右**固定一致**
- 一則訊息最多一組結構化 UI
- Agent 的訊息不要有頭像、不要有「AI」標籤、不要有打字動畫三個點以外的東西

## 任務與執行

```
API 文件

Agent 執行中 · 80%


已完成

✓ 分析 API 結構
✓ 撰寫認證章節


進行中

○ 產生範例


接下來

○ 最終檢查


[ 繼續 ]
```

規則：

- 三段：**已完成 / 進行中 / 接下來**。不要做成看板、不要有 ticket 編號、不要有指派人
- 已完成的用 `--color-text-secondary`，進行中的用 `--color-text`，接下來的用 `--color-text-muted`
- 進度條只有一條，放在狀態那一行旁邊；不要每個步驟都有進度條
- 使用者需要介入時，那個步驟要浮上來變成一個動作，而不是躺在清單裡等人發現

## Agent 狀態

八種狀態的呈現。用文字，指示點是輔助：

| 狀態 | 呈現 | 色 |
|---|---|---|
| 建議 | `建議` | `--color-text-secondary` |
| 等待核准 | `等待你確認` | `--color-warning` |
| 已排程 | `已排程 · 14:00` | `--color-text-secondary` |
| 執行中 | `執行中 · 80%` | `--color-accent` |
| 等待外部回應 | `等待 David 回覆` | `--color-text-secondary` |
| 需要注意 | `需要你處理` | `--color-warning` |
| 已完成 | `已完成 · 10 分鐘前` | `--color-text-muted` |
| 失敗 | `失敗 · 無法連線` | `--color-danger` |

規則：

- **失敗一定要帶原因與下一步**（「失敗 · 無法連線　重試 →」），只寫「失敗」等於把問題丟回給使用者
- 「等待核准」與「執行中」視覺上必須分得出來——這是使用者最常搞混的兩個
- 狀態指示點（8px 圓點）可選；**不要用旋轉、脈動或呼吸動畫**表示狀態

## 通知

```
Navo

會議 30 分鐘後開始
我已經準備好會議簡報。

查看簡報 →
```

規則：

- 三行：**發生什麼** → **Agent 已經做了什麼** → **一個動作**
- 標題不超過一行，內文不超過兩行
- 每則通知都要有一個明確動作；沒有動作的資訊不值得打斷使用者
- **不要因為 Agent 完成了一件背景小事就發通知**。判準：使用者現在不知道這件事會有損失嗎？不會就不發
- 同一件事的更新要取代前一則，不要堆疊

## 導航與 Agent 輸入

```
┌──────────────────────────────┐
│                              │
│         （內容）              │
│                              │
│  ┌────────────────────────┐  │
│  │ 問我任何事…             │  │
│  └────────────────────────┘  │
│                              │
│   首頁   探索   任務   我     │
└──────────────────────────────┘
```

規則：

- 主導航 3–4 項，只有名稱或只有圖示，**不要圖示配文字再配數字徽章**
- 選中用 `--color-text` 對比未選中的 `--color-text-muted`，不要用亮色或漸層
- Agent 輸入常駐但安靜：`--color-surface` 底、無框、placeholder 用 `--color-text-muted`
- 點進去之後才展開成完整的對話介面；在那之前不該主導畫面
- 語音按鈕可以有，但放在輸入框內側末端，不要做成畫面中央的大圓鈕

## 空狀態

```
還沒有需要你注意的事

我會在有狀況時通知你。
```

規則：

- 說明**為什麼是空的**與**接下來會發生什麼**，不要只寫「沒有資料」
- 不要放插圖，不要放「開始使用」的引導卡片
- 首次使用的空狀態才給一個動作（連接行事曆、授權信箱）
