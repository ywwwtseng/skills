# Calm UI：智慧來自行為，不是裝飾

給消費級的 AI 產品用的視覺與互動語言——AI 助理、agent 產品、服務中心、生產力與任務型 app。
所有數值在 `references/tokens.css`（可直接貼），五種畫面的版型與文案在 `references/patterns.md`。

**跟 `/ui:tonal-ui` 二選一。** 那套是後台與內部系統的淺色語言（白卡片、灰底、色塊分層）；
這套是消費級產品的深色語言。一個專案只能有一套，混用會得到一個既不像工具也不像產品的東西。

## 一句話

> **不要做一個後台再塞一個聊天框進去。**

使用者打開產品時該有的感覺是「事情已經在被處理了」，而不是「我有一堆事要管」。

## 核心互動模型

```
Agent 偵測 → Agent 摘要 → 使用者決定 → Agent 執行 → Agent 回報
```

介面要在**三秒內**回答三個問題：

1. 現在有什麼需要我注意？
2. Agent 已經在做什麼？
3. 它需要我做什麼決定？

答不出這三題的畫面，加再多視覺效果也沒有用。優先做**主動、帶上下文**的介面，而不是選單驅動的工作流。

## 三條原則

1. **智慧用行為表達，不用視覺表達。** 使用者感覺到智慧，是因為東西已經被做好了、下一步很明確、他不用自己去找。不是因為畫面上有一顆會發光的球。
2. **先問能不能刪掉。** 兩個設計選哪個，選元素更少、層級更清楚、裝飾更少、下一步更明確、使用者要管的事更少的那個。
3. **沒有東西在變的時候，畫面就該是靜止的。** 動效用來傳達狀態，不是用來證明產品很潮。

## 反 AI 陳腔濫調

**不要用視覺符號來表示「這裡有 AI」。** 這些預設全部不用：

發光球體、紫藍漸層色塊、到處的閃亮圖示、機器人圖示、大腦圖示、魔法棒圖示、浮動粒子、
能量特效、大量毛玻璃、霓虹色、裝飾性動畫。

要表達智慧，用這些：

上下文感知、主動的建議與摘要、自動化、進度、推薦、**已經完成的動作**、明確的下一步。

> 目標不是讓 AI 看起來很明顯，是讓產品感覺**已經被好好處理了**。

## 視覺語言

### 深色優先

克制的近黑色階。語意 token 見 `references/tokens.css`，起點值：

| 用途 | 值 |
|---|---|
| 頁面底 | `#0A0A0A` |
| 次層底 | `#111111` |
| 表面 | `#171717` |
| 浮起的表面 | `#222222` |
| 主要文字 | `#F5F5F5` |
| 次要文字 | `#A1A1A1` |
| 弱化文字 | `#6F6F6F` |

這些是起點不是硬性值，但**一律用語意 token**，畫面 CSS 裡不該出現色碼。

### 一個強調色

只給這些用：目前狀態、進度、確認、主要互動、品牌辨識。

**不要讓每個分類都有自己的顏色。** logo 很繽紛不代表介面要跟著繽紛。

### 框線與陰影

框線要極淡。要分隔之前先試間距、排版、表面對比——三個都試過了才考慮框線。

陰影要安靜。浮起來的東西（選單、對話框、toast）才有，而且要淡。

## 排版

**排版是主要的介面元素，不是配角。**

- 用系統字體
- 標題大而肯定，輔助文字安靜
- 短句
- 行高舒適、留白大方
- 字重變化少

**不要用圖示、卡片、漸層、顏色來補救層級不清楚。** 層級不清楚就是排版沒做好，加裝飾只會讓它更亂。

## 版面

垂直資訊流優先。留白要刻意，不是剩下的空間。

**不要把每個東西都塞進卡片。** 開一個容器之前先問：

> 排版、間距、對齊或一條分隔線，能不能表達這個層級？

可以的話就不要開卡片。優先長這樣：

```
標題
說明文字
中繼資訊

動作 →
```

而不是四張卡片疊在一起。卡片只在**資訊真的屬於一組**、或**需要獨立的互動狀態**時才用。

## 圖示

圖示次於內容。單色、線性、統一線寬、體積小、照平台慣例。

不要：每個圖示配一塊彩色方底、行事曆 / 檔案 / 信件各給一個顏色純粹為了裝飾、過大的圖示、裝飾性的 AI 圖示、每一列都有圖示。

**很多列不需要圖示也完全成立。** 導覽的選中狀態用克制的對比表示，不要用亮色漸層。

## 五種畫面

版型與文案範例見 `references/patterns.md`，這裡只講判準。

### 首頁 = Agent Feed，不是儀表板

依「需要注意的程度」排序，自然混合這幾種：需要使用者注意的、Agent 正在處理的、重要的即將發生的事、等待核准的決定、最近完成的有意義的工作。

**不要做成 widget 格狀牆。**

### 對話

輕量、自然，**多數訊息就是文字**。不要把每則 Agent 訊息都變成一張大卡片。

只有在能讓動作更好做時才引入結構化 UI：核准、確認、選擇、進度、排程、外部動作、審閱產出的內容。

要有對話感，但不要變成一個通用聊天機器人。

### 任務與執行

不要做成 Jira ticket。使用者要知道的是：發生了什麼、已經完成了什麼、現在在做什麼、接下來是什麼、需不需要我介入。

用「已完成 / 進行中 / 接下來」三段，進度不必打開另一個管理頁就看得懂。

### 通知

通知是產品體驗的一部分，不是附加功能。要有上下文、簡短、可行動、及時、低噪音。

**不要因為 Agent 做了一件不重要的背景操作就發通知。**

### 導航與輸入

主導航 3–4 個目的地。不要把每個產品能力都變成一個常駐的導航項目。

Agent 的互動可以獨立於導航之外：一個輕量的常駐輸入（「問我任何事」），在使用者點它之前不該主導畫面。語音可以有，但不要讓整個介面長得像語音助理。

## Agent 狀態

**狀態必須明確。** 使用者永遠不該猜「它是建議、還是在等我同意、還是已經在做了、還是做完了」。

八種狀態：`建議` / `等待核准` / `已排程` / `執行中` / `等待外部回應` / `需要注意` / `已完成` / `失敗`。

用精簡的文字加克制的狀態指示，**不要靠裝飾性動畫表達狀態**。

## 動效

動效傳達狀態，不是裝飾。

可以用：細微的載入、進度轉換、狀態轉換、內容柔和出現、確認回饋。

不要用：持續移動的裝飾元素、浮動發光物件、粒子、脈動的 AI 能量、過度視差。

## 行動優先

除非任務明確要求桌面優先，一律先設計行動版。

舒適的點擊區、主要動作放拇指好按的位置、清楚的垂直層級、safe area、導航層級淺、內容可讀不過度密集。

**不要把桌面儀表板縮小塞進手機。**

## 動手前的七個問題

設計任何畫面之前，先在心裡回答：

1. 使用者需要知道什麼？
2. Agent 已經知道什麼？
3. Agent 正在做什麼？
4. 什麼需要使用者注意？
5. 需要什麼決定？
6. 唯一的下一步是什麼？
7. **這個畫面上有什麼可以刪掉？**

答完再設計。

## 改版既有介面的順序

被要求改版時照這個順序走，**不要跳到最後一步**：

1. 弄懂使用者的目標
2. 找出資訊層級
3. 找出什麼需要注意
4. 找出 Agent 已經知道什麼
5. 找出 Agent 正在做什麼
6. 找出唯一最有意義的下一步
7. 刪掉不必要的 UI
8. 減少卡片數量
9. 簡化圖示
10. 增加有用的留白
11. 改善排版與層級
12. 把 Agent 的上下文與進度顯示出來
13. **最後**才處理顏色、表面與視覺打磨

> 版面弱不要用漸層和特效來解決。

## 交件前檢查清單

- [ ] 這像消費級產品還是後台？像後台就重來。
- [ ] 三秒內看得出什麼需要注意嗎？
- [ ] Agent 是主動的還是只會回應？
- [ ] 現在 Agent 在做什麼，看得出來嗎？
- [ ] 最有意義的下一步明顯嗎？
- [ ] 有沒有不必要的卡片？把不屬於一組的拆回純排版。
- [ ] 有沒有不必要的圖示？很多列不需要圖示。
- [ ] 有沒有不必要的顏色？分類不需要各自的顏色。
- [ ] 有沒有不必要的框線？先試間距與表面對比。
- [ ] 有沒有 AI 陳腔濫調（發光球、漸層、閃亮、機器人）？
- [ ] 留白有沒有在做事？
- [ ] 顏色、字級、圓角、間距是不是都用 token，沒有寫死？
- [ ] 把所有視覺效果關掉，這個介面還成立嗎？
- [ ] 它感覺 calm 嗎？

任何一題露出多餘的複雜度 → **再簡化一次**。

## 換一個技術棧怎麼落地

規則不變，落點不同：

- **CSS / CSS Modules**：`references/tokens.css` 直接貼進全域 `:root`。
- **Tailwind**：token 填進 `theme.extend`，只用 theme 裡的名字，不要用 `bg-[#0A0A0A]` 這種任意值。
- **React Native / Expo**：token 變成 `theme.ts` 常數物件；深色優先在行動端更自然（省電、夜間可讀）。safe area、44pt 最小點擊區、拇指區照舊。
- **任何棧**：先把 token 定好再寫畫面。**先寫死顏色之後再抽 token，最後一定會漏。**

## 常見失敗模式

| 症狀 | 為什麼是錯的 |
|---|---|
| 做了一個儀表板，右下角加一顆聊天泡泡 | Agent 變成附加功能，產品還是要使用者自己管事 |
| 首頁是一面 widget 牆 | 使用者要自己掃描才知道什麼重要，三秒法則直接失敗 |
| 每則 Agent 訊息都是一張卡片 | 對話變成表單，輕量感消失 |
| 用發光球 / 漸層表示「這是 AI」 | 智慧要從行為看出來；視覺符號只是在說「我們有接 API」 |
| 每個分類一個顏色 | 沒有東西被強調，等於沒有強調色 |
| 層級不清楚就加卡片和圖示 | 那是排版沒做好，加裝飾只會更亂 |
| 每一列都放圖示 | 圖示變成噪音，內容被擠掉 |
| 任務做成 Jira 看板 | 使用者要的是「做到哪了、要不要我介入」，不是工單管理 |
| Agent 狀態靠一個轉圈動畫表示 | 分不出它是在等我同意、還是已經在做 |
| Agent 做完背景小事就發通知 | 通知失去價值，之後重要的也會被忽略 |
| 改版時先換配色 | 版面弱不會因為換色變強（改版順序第 13 步） |
