# 規則 → 模型元素對應

依規則文件的「類型」欄逐條分派。一條規則可以產生多個元素；每個元素的「來源」欄記錄它來自哪些規則 ID。

## 模型元素一覽

| 元素 | 定義 | 判斷方式 |
|---|---|---|
| 實體 Entity | 有身分（識別碼）、屬性會隨時間變、身分不變 | 「兩個屬性完全相同的 X 是不是不同的東西？」是 → 實體 |
| 值物件 Value Object | 沒有身分，屬性相同即相等，通常不可變 | 「換成另一個屬性相同的 X 有沒有差別？」沒有 → 值物件 |
| 列舉 Enum | 有限個固定值 | 狀態、角色、等級、類型、幣別 |
| 衍生屬性 Derived | 由其他屬性算出，不獨立輸入 | 規則寫「X = …」或「X 為 … 的 …」 |
| 不變量 Invariant | 任何時刻都必須成立的條件 | 約束類規則，掛在能守住它的實體或值物件 |
| 聚合 Aggregate | 一組實體 + 值物件，作為一個整體維持不變量；有一個聚合根 | 「這條不變量需要同時看哪些實體？」它們同屬一個聚合 |
| 關聯 Relationship | 實體之間的參照 | 方向、基數、擁有權 |
| 命令 Command | 使用者或系統對聚合做的一個動作 | 「事件 / 動作」列、狀態轉換的觸發者 |
| 領域事件 Domain Event | 已經發生、不可否認的事實（過去式） | 狀態轉換成功、命令成功、觸發類規則的「當…時」 |
| Policy | 「當〈事件〉時執行〈命令〉」或跨實體的規則 | 觸發類、時間類、跨聚合的約束 |
| Domain Service | 跨多個聚合的計算或判斷，不屬於任何單一實體 | 跨實體的計算類規則 |

## 各類型規則的分派細則

### 1. 定義與推導值

- 名詞定義 → 判斷是實體 / 值物件 / 列舉，寫進該元素的「定義」欄
- 「相同」的判定基準 → 值物件的相等性規則（例：「相同商品 = 同 SKU」→ `ProductRef` 以 SKU 相等）
- 推導值 → 衍生屬性，記錄：公式（引用計算規則 ID）、計算時機（即時 / 快照）、來源改變時是否重算
- 推導值若跨聚合（「活躍客戶」需看訂單） → 放在被描述的實體上，標「跨聚合，由 policy 更新」或做成 domain service 查詢

### 2. 約束與驗證

- 單一欄位格式 / 範圍 → 該屬性的型別約束（值物件最適合：`Money` 不可為負、`Email` 格式）
- 唯一性 → 不變量，寫明範圍（全域 / 某父實體內）；全域唯一通常暗示這是實體的識別碼或需要 domain service 檢查
- 前置條件（動作執行前必須…） → 命令的前置條件，引用不變量 ID
- 數量上下限 → 聚合根的不變量（「訂單最多 50 項」掛在 Order）
- 「違反時」的處理方式 → 命令的失敗結果（阻擋 → 命令拒絕；警告後放行 → 命令成功但發出警告事件；自動修正 → 命令成功且修正值）

### 3. 計算

- 單一實體內的算式 → 衍生屬性
- 涉及金額 / 數量 / 時長的運算 → 值物件的運算（`Money.add`、`Money.multiply` 含進位規則）
- 跨聚合 → domain service，輸入輸出都用值物件
- 「凍結」（成立後不隨來源變） → 從衍生屬性改為一般屬性，在命令執行時計算並寫入，標明凍結時機

### 4. 狀態流轉

- 所有狀態 → 狀態列舉
- 每一列轉換 → 狀態機的一條轉換：從 / 到 / 命令 / 前置條件 / 發出的事件
- 「系統自動轉為…」 → 由排程 policy 發出命令，不是實體自己動
- 終態（無出邊） → 標記，命令前置條件會用到（「已取消不可再變更」）

### 5. 權限

- 角色 → 角色列舉
- 誰可以做什麼 → 命令的「允許執行者」欄；條件式權限（「僅能修改自有訂單」）寫成命令前置條件
- 權限矩陣整表照搬進模型的命令表，不重新編排

### 6. 時間與排程

- 時間點屬性 → `時間點` 型別，標明時區來源
- 有效期間 → 值物件 `期間`（起、迄、含不含端點）
- 「每日 00:00 …」 → 排程 policy：觸發時間、執行的命令、影響的聚合
- 時間窗（「5 分鐘內」） → 值物件 `時間窗` 或 policy 的參數，標明滑動 / 固定

### 7. 觸發與副作用

- 「當 A 成功時要 B」 → A 產生領域事件（過去式命名：`訂單已建立 OrderCreated`），B 是處理該事件的 policy
- 通知、寄信、同步外部系統 → policy，模型只記錄「要發生什麼」，不記錄怎麼發
- 副作用失敗是否影響主動作 → 寫進 policy 的「失敗處理」

### 8. 例外與覆寫

- 例外規則 → 掛在被例外的不變量 / policy 下，寫成「除非 …」條款，引用例外規則 ID
- 覆寫（管理員可強制…） → 命令多一個允許執行者，前置條件放寬，並發出不同事件（`訂單已強制取消`）
- 優先序 → 直接照規則文件的「規則間的優先序」寫進 policy 的評估順序

## 關聯怎麼從規則推出來

關聯不是看名詞出現就連線，而是從規則的句型推出來。每條關聯都要能指回產生它的規則。

| 規則裡的句型 | 推出的關聯 | 補充要寫的 |
|---|---|---|
| 「X 的 Y」（訂單的項目、客戶的地址） | X 擁有 Y；Y 隨 X 生滅 | 基數上下限（若規則有寫）、是否同聚合 |
| 「X 屬於 / 對應 Y」（訂單屬於客戶） | X 參照 Y，通常跨聚合，X 持有 Y 的識別碼 | 可否變更、Y 消失時 X 怎麼辦 |
| 「同一 X 內不可 / 最多 N 個 Y」 | 關聯上的不變量，掛在 X（聚合根） | INV ID、檢查時機 |
| 「自有的 X」「自己的 Y」（權限類） | X → 執行者 的關聯 + 命令前置條件「執行者必須是 X 的擁有者」 | 引用權限規則 ID |
| 「X 成立 / 建立時記錄 Y」 | 建立時機 = 該命令；若規則寫「之後不得更改」→ 可否變更 = 否 | 對應的不變量 |
| 「刪除 / 停用 X 時 Y …」 | 解除時機；「Y 保留」= 無擁有權，「Y 一併刪除」= 擁有 | 引用規則 ID |
| 「X 與 Y 相同時 …」（相同商品） | 不是關聯，是值物件的相等性 | 放到值物件段 |

**關係名要帶動詞、寫雙向**（客戶 **下** 訂單 ／ 訂單 **屬於** 客戶）。動詞從規則文件的陳述句抄，不自己發明；兩邊都寫是為了讓讀者從任一實體出發都能找到這條關聯。

**寫進關聯的東西 vs 寫進別處的東西**

- 關聯本身：關係名、方向、基數、擁有權、跨聚合、建立 / 變更 / 解除時機
- 關聯上的規則（數量上限、不可換對象、需要對方處於某狀態）：立成不變量或 policy，關聯段只引用 ID，避免同一條規則在兩處各寫一版
- 關聯的儲存方式（join table、外鍵、索引）：不寫，屬於 schema

**基數寫法**：`1 → 0..*`、`1 → 1..50`、`0..1 → 1`；左邊是「從」、右邊是「到」。規則沒寫上限就用 `*`，並在假設清單記一筆「無上限」。

**跨聚合的判斷**：被同一條不變量綁在一起 → 同聚合，關聯是直接持有；否則跨聚合，只持有識別碼，並寫明「對方消失時怎麼辦」（保留識別碼 / 禁止對方刪除 / 一併處理），這通常對應規則文件裡刪除類的邊界條件。

## 概念型別表

模型只用這些型別，不用程式語言或資料庫型別：

| 概念型別 | 說明 | 不要寫成 |
|---|---|---|
| 識別碼 | 實體身分，不透明 | uuid、bigint、auto increment |
| 文字 | 自由文字；有格式要求時抽成值物件 | varchar(255)、string |
| 整數 / 小數 | 標明單位與範圍；有進位規則時抽成值物件 | int、decimal(10,2) |
| 金額 | 值物件：數值 + 幣別 + 進位規則 | number |
| 時間點 | 含時區的絕對時間 | timestamp、Date |
| 日期 | 不含時間；標明時區 | date |
| 時長 | 一段長度 | int（秒） |
| 期間 | 值物件：起 + 迄 + 端點含不含 | 兩個 timestamp 欄位 |
| 布林 | 是 / 否 | tinyint |
| 列舉〈名稱〉 | 引用列舉 | string、int |
| 〈實體〉參照 | 跨聚合只持有識別碼 | foreign key |
| 集合〈型別〉 | 標明有序 / 無序、可否重複、上下限 | JSON、join table |
| 可選〈型別〉 | 可以沒有值；寫明「沒有值代表什麼」 | nullable |

## 聚合邊界的判斷

1. 列出所有不變量。
2. 每條不變量圈出它需要同時檢查的實體。
3. 被同一條不變量圈在一起的實體必須在同一個聚合。
4. 沒被任何不變量圈在一起的實體分屬不同聚合，彼此只用識別碼參照。
5. 聚合根是外界唯一可以操作的入口：所有命令都對著聚合根。
6. 聚合太大（一個聚合 > 5 個實體）通常代表把值物件當成了實體，或不變量其實可以放寬成最終一致。

## 常見錯誤

| 錯誤 | 為什麼不好 | 改法 |
|---|---|---|
| 每個名詞都做成實體 | 聚合膨脹，不變量守不住 | 用身分測試，能當值物件的就當值物件 |
| 金額用「小數」 | 幣別、進位規則散落各處 | 抽成 `金額` 值物件，進位規則寫一次 |
| 狀態用布林（`isCancelled`、`isPaid`） | 狀態組合爆炸，非法組合無法防 | 一個狀態列舉 + 狀態機 |
| 命令直接寫副作用 | 副作用失敗會拖垮主動作 | 命令發事件，policy 處理副作用 |
| 模型裡寫 table 名、索引 | 儲存方式反過來綁住領域 | 移到規則文件的「實作提示」 |
| 模型元素沒有來源規則 | 憑空想像的結構之後沒人敢改 | 標「推導 / 假設」並寫理由，或刪掉 |
| 關聯只畫線不寫語意 | 「Order — Customer」看不出誰下單、能不能換 | 關係名帶動詞、寫雙向，補建立 / 變更 / 解除時機 |
| 每兩個名詞一起出現就連線 | 關聯爆炸，多數沒有規則支撐 | 只從規則句型推關聯，每條都要有來源 ID |
| 關聯規則寫在關聯段又寫在不變量段 | 改一處漏一處 | 規則只立一次 INV / POL，關聯段引用 ID |
